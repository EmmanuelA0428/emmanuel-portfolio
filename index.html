BluePrint Geneva

Geneva Community Air Quality Dashboard

A community air quality platform that collects and processes environmental sensor data, then presents maps, trends, and air quality information for residents and advocates.

Python Shiny BigQuery Google Cloud GIS

Live demo

Case study

Problem

Six community RAMP sensors produced minute-level readings, but data lived in a vendor portal that was inaccessible to the public.

What I Built

An automated ingestion pipeline and a public Shiny dashboard that present sensor readings as EPA AQI categories, maps, trends, freshness indicators, and clear notes on coverage limits—aimed at community communication, not regulatory-grade measurements.

Technical Approach

  • Integrated six Sensit RAMP sensors through the Sensit Connect API.
  • Automated ETL on Google Cloud: Cloud Scheduler → Pub/Sub → Cloud Function → BigQuery.
  • Validation, completeness thresholds, temporal aggregation, and AQI calculations before visualization.
  • Interactive public dashboard (maps, trends, sensor health) deployed on Cloud Run.

Status & Results

Public demo dashboard is deployed (see live demo link). Presented the work as a poster at the Air Sensors International Conference, Los Angeles, May 2026. The interface emphasizes accessibility and uncertainty—not regulatory-grade certainty.

Hobart and William Smith Colleges · Center for Teaching and Learning

Accommodated Exam Testing

A Windows desktop application that guides staff and students through exam setup, approved accessibility tools, testing, and document recovery.

C# WPF PowerShell Word automation

Status: Beta / pilot validation

Case study

Problem

Staff prepared testing laptops step by step—USB exam files, Wi‑Fi changes, saves, and clearing Word history between students. Helper tools covered individual tasks, but staff still coordinated the full sequence manually.

What I Built

A Windows desktop application that supports accommodated testing from setup through export and machine restoration. Primary workflow: offline Microsoft Word exams. Supported workflow: online exams in Microsoft Edge (Canvas, Posit).

Technical Approach

Accessibility

Integrates approved Windows dictation (Voice Access) and text-to-speech for selected text. Staff configure approved supports during setup; students access them during the exam.

Session workflow and recovery

  • Managed sessions: preparation, document import, testing, staff review, export, restoration.
  • Word automation for document operations; a privileged background service applies approved settings.
  • Automatic Word saves, rolling recovery copies, a Finish checkpoint, file-hash checks on export, and a recovery path before the next session.

Testing controls

Mode-specific controls for Wi‑Fi, USB storage, and browser access; focus-return assistance and staff-PIN handoff. Prior machine settings are recorded so the app can restore them afterward. Not a secure lockdown browser or guarantee against unauthorized access or data loss.

Built with C#, WPF/XAML, Word COM automation, and PowerShell, with separate UI, session-model, and service layers.

Status & Results

Beta / pilot validation (documented release: Beta 4.5). Not described as institution-wide production deployment. No confidential student data, exam content, or internal procedures are published here.

Success for Geneva's Children

Success for Geneva's Children — Integrated Internal Dashboard

An internal dashboard that helps staff maintain community indicator data, explore trends, and create report-ready charts—with role-based access and centralized data management.

R Shiny ggplot2 PostgreSQL
Case study

Problem

Community reporting drew from state portals, Census data, schools, and local partners. Manual collection made updates, backups, and source tracing difficult across ten community goals.

What I Built

An internal R Shiny application where staff can maintain datasets, explore indicators, monitor refresh and attribution, and build exportable charts—with viewer, editor, and administrator roles.

Technical Approach

  • Maintaining datasets — in-app editor to update, view, back up, and restore community indicator files tied to each goal.
  • Exploring indicators — plot builder with filters, captions, exports, and a data table aligned to each chart.
  • Pipelines and sources — system views for dataset catalog, activity log, and tooling to refresh data and retain source metadata (including automated fetcher integration and a PostgreSQL registry on Neon).
  • Access control — role-based permissions for viewing, editing, and administration.

Stack includes R, Shiny, bslib, ggplot2, and Neon-hosted PostgreSQL where documented in the project.

Status & Results

Internal staff dashboard (not a public site). Delivers the capabilities above for authorized users; operational impact and time savings are not documented on this portfolio.

NYC Transportation Safety & Income Analysis

Analysis of approximately 65,000 NYC motor-vehicle collision records (2024, after cleaning/filtering) joined with Census household-income estimates at ZIP-code geography.

Compared raw collision totals with rates per 100,000 households. Normalization changed how collision, injury, and fatality patterns read across areas; household-normalized rates are not direct measures of individual travel risk.

Findings describe associations in the analyzed data, not causal effects.

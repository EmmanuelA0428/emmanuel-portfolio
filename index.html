BluePrint Geneva

Geneva Community Air Quality Dashboard

An end-to-end community air quality monitoring platform that collects, processes, analyzes, and visualizes environmental sensor data for residents and advocates.

Python Shiny BigQuery Google Cloud GIS

Live demo

Case study

Problem

Six community RAMP sensors produced minute-level readings, but data lived in a vendor portal, which was inaccessible to the public.

Solution

Built an automated cloud pipeline and a public Shiny dashboard that translate sensor readings into EPA AQI categories, maps, trends, freshness indicators, and honest communication of coverage limits.

Implementation

  • Integrated six Sensit RAMP sensors through the Sensit Connect API.
  • Developed automated ETL on Google Cloud (Scheduler → Pub/Sub → Cloud Function → BigQuery).
  • Applied validation, completeness thresholds, temporal aggregation, and AQI calculations.
  • Deployed an interactive public dashboard (maps, trends, sensor health) on Cloud Run.
  • Infrastructure supports roughly 3.15 million potential sensor records per year (six sensors, one reading per minute).

Outcomes

Presented the dashboard at the Air Sensors International Conference (Los Angeles, May 2026). Dashboard emphasizes accessibility and uncertainty, not regulatory-grade certainty.

Hobart and William Smith Colleges · Center for Teaching and Learning

CTL TestDesk — Accommodated Exam Management

A Windows desktop application that unifies staff-managed accommodated exam preparation, document handling, accessibility configuration, export, and recovery — replacing a fragile USB-and-Word workflow.

C# WPF PowerShell Word automation

Status: Beta / pilot validation (documented release: CTL TestDesk Beta 4.5).

Case study

Problem

Staff prepared accommodated exams via manual laptops: Word files from USB drives, Wi‑Fi disabled, saves back to removable media, and clearing recent-document history between students.

Solution

Desktop app with separated UI, session models, services, and configuration scripts. Primary workflow: offline Word examinations; secondary workflow: online exams in Microsoft Edge (Canvas, Posit).

Implementation (documented architecture)

  • Session lifecycle: preparation, active testing, completion, staff review, verified export, recovery.
  • Word import/automation, working copies, save verification, recovery snapshots.
  • File-hash verification for transfers and exports.
  • Windows Voice Access integration for speech-to-text (not a custom speech model).
  • PowerShell integration for approved machine-level changes and restoration.

Scope boundaries

Focus assistance — not a secure browser, tamper-proof exam system, or complete OS lockdown solution. No confidential student data, exam content, or internal procedures are published here.

Success for Geneva's Children

Success for Geneva's Children — Integrated Internal Dashboard

Modular R Shiny stewardship app (v4) for community indicator data: goal-level overview, in-app dataset maintenance, report-mode exploration, system diagnostics, and role-based access on a Neon-backed registry.

R Shiny bslib ggplot2 Neon Postgres
Case study

Problem

Community reporting drew from state portals, Census data, schools, and local partners. Repeated manual collection made updates, backups, and source tracing difficult for staff maintaining ten community goals.

Solution

Built an integrated internal dashboard that unifies stewardship, exploration, and pipeline visibility in one bslib-themed Shiny application, with authenticated roles (viewer, editor, administrator) and a central dataset registry.

Implementation

  • Overview — goal sidebar, dataset cards per community goal, and an in-app dataset editor (update, view, backup, restore).
  • Explore (Report Mode) — plot builder with goal/dataset filters, exports, captions, and a filtered data table aligned to each chart.
  • System & Diagnostics — health stats, dataset catalog (including archive/restore), activity log, and administrator user management.
  • Data layer — Neon Postgres registry, automated fetcher registry integration, and pipeline tooling for refresh and attribution metadata.
  • In-app assistant — context-aware help grounded in dashboard structure and permissions.

Outcomes

Staff can refresh indicators, trace sources, and produce report-ready visuals from one interface instead of ad hoc spreadsheets and disconnected files.

NYC Transportation Safety & Income Analysis

Analyzed approximately 65,000 NYC motor-vehicle collision records (2024, after cleaning/filtering) with Census household-income estimates at ZIP-code geography. Compared raw collision totals with rates per 100,000 households — normalization changed the interpretation of collision, injury, and fatality patterns.

Findings describe associations in the analyzed dataset, not causal claims. Income, infrastructure, vehicle safety, and emergency response remain hypotheses for further study.
